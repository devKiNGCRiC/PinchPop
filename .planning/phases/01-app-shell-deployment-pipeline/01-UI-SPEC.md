# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase scaffolds the React app shell itself — no `package.json`/`src/` exists yet in the repo. There is no `components.json` to detect. This contract therefore doubles as the **base design system for the whole product** (per phase context: this is the first visual impression and every later phase builds on it), not just a placeholder-skeleton spec.

**Source of brand direction:** the existing vanilla-JS prototype's `css/styles.css` already establishes a distinctive, intentional visual identity — a dark "darkroom/viewfinder" stage (mono, uppercase, letter-spaced HUD chrome, amber signal accent) paired with a light "photo-paper" panel for content (the gallery sidebar). This contract carries that identity forward as reusable design tokens for the whole app shell, not just the game canvas. The literal legacy `css/styles.css` file itself stays scoped to the ported game screen only (Phase 2), per RESEARCH.md/STACK.md — this phase re-expresses the same token *values* through Tailwind v4 theme variables so chrome/landing/placeholder pages match instead of looking like an unrelated generic SaaS UI bolted onto a photobooth game.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: Nav bar icon buttons and the mobile hamburger trigger use a 44×44px minimum hit target (accessibility floor for touch, not a spacing-scale value) even though the visible icon itself renders at 20-24px — required for SHELL-04 mobile responsiveness.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 13px | 400 (regular), uppercase, `letter-spacing: 0.08em` | 1.4 |
| Heading | 28px | 600 (semibold) | 1.2 |
| Display | 48px | 600 (semibold) | 1.1 |

Font family: `Label` role always uses `IBM Plex Mono` (matches existing HUD/status-pill/brand-wordmark convention). `Body`, `Heading`, and `Display` use `Inter`. Exactly 2 weights declared (400, 600) — do not introduce 500/700 anywhere in this phase.

Mobile scaling: `Display` drops to 32px and `Heading` to 22px below the `md` (768px) breakpoint — same weights/line-heights, size only.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a08` (ink) | App/page background, nav bar, footer, hero section, all placeholder-page backgrounds |
| Secondary (30%) | `#ffffff` (paper-white, paired with border `#e3e0d8`) | Content-card surfaces: results card, gallery grid backdrop, profile card, share card — the "photo tray" surface family already established by the prototype's gallery panel |
| Accent (10%) | `#f5c518` (signal) | See reserved-for list below — never used generically |
| Destructive | `#e0533d` (danger) | Destructive actions and error states only |

Accent (`#f5c518`) reserved for:
- The single primary CTA button per screen (e.g. "Start Playing" on the landing/home page)
- Active nav-link indicator (2px underline/bottom-border on the current route)
- Focus-visible outline ring on interactive elements
- "Live" status indicators inherited from the prototype pattern (e.g. a future recording dot) — not used in Phase 1's static placeholder pages, but the token is reserved for this purpose so later phases don't redefine it
- Do NOT use accent for: body links, secondary/ghost buttons, decorative icons, or general hover states — those use neutral ink/paper tones with opacity shifts

Destructive (`#e0533d`) reserved for:
- Error/404 page accent and error banners
- Future destructive confirmations (delete photo in Phase 6, revoke share link in Phase 8) — token reserved now for consistency, not used against live functionality in Phase 1 since no destructive actions exist yet

Supporting neutrals (not part of the 60/30/10 split, but needed for text-on-dark and dividers): `#eae5d6` (paper, warm off-white text on ink backgrounds), `#6b665c` (muted ink-soft text on paper surfaces), `#e3e0d8` (paper-surface borders).

## Layout & Breakpoints

Tailwind v4 default breakpoints, used as-is (no custom scale):

| Breakpoint | Width | Behavior |
|------------|-------|----------|
| Mobile (default) | < 640px | Single-column stack, nav collapses to hamburger → Sheet drawer |
| `sm` | ≥ 640px | Same as mobile, wider gutters |
| `md` | ≥ 768px | Nav bar expands to full horizontal link row; `Display`/`Heading` sizes step up |
| `lg` | ≥ 1024px | Max content width `1200px`, centered; multi-column placeholder grids (e.g. gallery placeholder grid) |

**Navigation pattern:** persistent top nav bar, dark ink background (`.hud-top` visual lineage), full-width, `h-16` (64px) tall. Left: mono uppercase wordmark "PINCHPOP" in `Label` style, signal-colored. Right (≥768px): horizontal nav links (Home, Play, Gallery, Profile) in `Label` style, active route gets a 2px signal-colored bottom border. Below 768px: wordmark stays left, a 44×44px hamburger icon-button replaces the link row and opens a right-side `Sheet` drawer with the same links stacked vertically. The hamburger button carries `aria-label="Open navigation menu"` (icon-only control, no visible text).

**Footer:** minimal single line, centered, `Label` style at reduced opacity (`~30%`) on ink background — carries forward the existing `.copyright` pattern. Must include preserved PuzzleCam attribution per PROJECT.md's non-negotiable constraint (e.g. "PinchPop — built on PuzzleCam by Unnati-23").

**Page shell:** every route renders inside a shared `<AppShell>` (nav + `<Outlet />` + footer). Placeholder pages are vertically centered content blocks on the ink background using a `Secondary` (paper-white) card for any content that needs to read as a discrete surface (e.g. the results/gallery/profile placeholder message).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Start Playing" (landing/home → `/game`, satisfies SHELL-02) |
| Empty state heading | "{Feature} coming soon" (per-route table above — each placeholder route uses this exact pattern with its own noun) |
| Empty state body | "{One sentence: what will live here + which future phase unlocks it}" (per-route table above) — always names the *reason* it's not ready, never a bare "Coming Soon" with no context |
| Error state | 404/unmatched route — heading: "Page not found." Body: "We couldn't find that page. Head back and keep exploring PinchPop." CTA: "Back to Home" (links to `/`) |
| Destructive confirmation | None in this phase — no delete, revoke, or sign-out actions exist yet. Token/pattern reserved for Phase 4 (sign-out) and Phase 6/8 (delete/revoke), not defined here. |

## Implementation Notes (shadcn initialization)

`components.json` does not exist because the React app has not been scaffolded yet — that scaffolding is itself Phase 1's deliverable. The standard shadcn init gate (interactive Y/n + pasted preset string) cannot run inside this research session because there is no Vite project yet to run it against. Recommended sequence for the **planner/executor** to follow as an early Phase 1 task, in order:

```bash
npm create vite@latest . -- --template react-ts
npm install tailwindcss @tailwindcss/vite
npm install zustand @mediapipe/tasks-vision @supabase/supabase-js react-router-dom
# configure Tailwind v4 per @tailwindcss/vite docs, then:
npx shadcn init
#   → style: new-york
#   → base color: neutral
#   → CSS variables: yes
npx shadcn add button card sheet separator skeleton badge
```

After init, extend the generated Tailwind theme's CSS variables with the token values declared in the Color section above (ink/paper/signal/danger) rather than shadcn's default neutral palette — this is what keeps the new chrome visually aligned with the existing prototype's brand identity. Do not import the legacy `css/styles.css` file into the new app shell; it stays scoped to the Phase 2 game-screen port.
