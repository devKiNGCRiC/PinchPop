# Phase 1 — UI Design Contract (REVISED — Revision 3, reconciled with DESIGN.md)

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Revision 3 reconciled by hand against the approved root `DESIGN.md`.

## Revision 3 — Reconciliation Note

**Why this revision exists:** The root `DESIGN.md` ("PinchPop — Visual Design System") was approved as the project's authoritative visual source of truth, built independently from three Google Stitch concept explorations rather than from this document. Revision 2 (below) and `DESIGN.md` landed on the same overall direction — warm paper base, coral shutter accent, Space Grotesk/Inter/IBM Plex Mono type system, camera/photobooth visual motifs — but differed in specific hex values, in how decorative color is scoped, and in a few typography and interaction details. This revision reconciles Revision 2 to `DESIGN.md` exactly, per explicit instruction: **`DESIGN.md` is authoritative wherever the two disagree.**

**What did NOT change again:** the seven-route structure, `createBrowserRouter` nested-layout architecture, `AppShell`/`NavBar`/`MobileNavSheet`/`PlaceholderCard` component boundaries, the copywriting contract's actual strings, the spacing scale, the breakpoints, the shadcn component inventory, and the `radix-vega` shadcn preset. Executors should again treat this as a **token and detail-level correction pass**, not a rearchitecture.

**Conflicts found and how each was resolved (DESIGN.md wins in every case):**

1. **Every named color's hex value differed slightly from `DESIGN.md`'s token table** (e.g. Cream `#FFF8EF` vs. `DESIGN.md`'s `paper` `#FBF1E4`; Shutter Coral `#FF5A47` vs. `shutter` `#FF5A3C`; Aperture Ink `#1D1626` vs. `ink` `#221A14`). **Resolution:** every hex value below is now copied verbatim from `DESIGN.md` §3, and token names are aligned to `DESIGN.md`'s naming (`paper`, `paper-raised`, `paper-border`, `ink`, `ink-soft`, `shutter`, `shutter-ink`, `danger`) so the two documents can be diffed against each other going forward.
2. **The "Decorative Motif Palette" (Flash Pink, Viewfinder Blue, Darkroom Violet, Flash Lime) was used app-wide** — as gradient-blob colors on the landing hero, as per-route icon tints on every stub page (`/game`, `/results`, `/gallery`, `/profile`, `/share/:slug`), as a puzzle-grid icon accent, and as a card-shadow tint — while `DESIGN.md` reserves decorative color exclusively for "Home and other promotional surfaces... and even there, sparingly" (`DESIGN.md` §10, §21) and otherwise requires every accent to have one specific, non-decorative job (§3). **Resolution:** the four colors are kept (their exact hues aren't specified by `DESIGN.md`, which explicitly leaves room for a landing-only "soft abstract gradient" treatment), but are renamed **Landing Gradient Wash** and re-scoped to the Home hero's background layer only — see the Color section below. All per-route icon tinting, the puzzle-grid icon tint, and the violet-tinted card shadow are removed; icons (where used) render in `ink`, and card shadows use a neutral `ink`-tinted wash instead. One color, "Viewfinder Blue," is additionally renamed to **Lens Blue** to avoid colliding with `DESIGN.md`'s unrelated `viewfinder` token (a teal, reserved for live gesture-tracking HUD state — a completely different color and job).
3. **`DESIGN.md` defines three additional functional accents Revision 2 didn't have:** `viewfinder` (`#1E9E8C`, live-tracking teal), `token-gold` (`#FFC531`, score/currency), and `neon-violet` (`#7B5CF0`, puzzle-active-tile state). **Resolution:** all three are added to the palette below as reserved tokens. None has a live use in Phase 1's actual scope — there is no real camera feed (`viewfinder`'s job), no real score display (`token-gold`'s job), and no real interactive puzzle grid (`neon-violet`'s job) until Phase 2. They are documented and reserved exactly the way `danger`/Ruby already was in Revision 2, so Phase 2 doesn't have to invent them.
4. **Display type size was 60px/36px (desktop/mobile); `DESIGN.md` §4 specifies 56px/34px.** **Resolution:** corrected to 56/34.
5. **Revision 2 declared exactly 2 weights (400, 700) and explicitly dropped the `@fontsource/inter` 600 import; `DESIGN.md` §4's type table lists Inter at both 400 and 600.** **Resolution:** Inter 600 is reinstated as an available Body-role weight (for emphasis/button labels), and the "exactly N weights" rule is restated to match `DESIGN.md`'s actual set: Space Grotesk 700, Inter 400/600, IBM Plex Mono 400 — three weights total, still a hard ceiling, just corrected.
6. **`DESIGN.md` §19 requires `prefers-reduced-motion` handling for every hover/press/celebratory animation; Revision 2's shutter-click micro-interaction and card hover-lift didn't mention it.** **Resolution:** added explicitly to both.
7. **Everything else** (nav structure, footer, breakpoints, route/copy table, component inventory, registry safety) was already compatible with `DESIGN.md` and is preserved unchanged — see the per-section notes below for the specific compatibility checks performed.

| Role | Size (desktop) | Size (mobile, < 768px) | Weight | Line Height |

**Reconciled against `DESIGN.md` §4:** Display size corrected from Revision 2's 60px/36px to `DESIGN.md`'s 56px/34px. Inter's 600 weight, which Revision 2 dropped, is reinstated for Body-role emphasis and button labels, matching `DESIGN.md`'s type table exactly.

`@fontsource` packages: `@fontsource/space-grotesk` (weight 700 only), `@fontsource/inter` (weights 400 **and 600** — the 600 import that Revision 2 dropped is restored), `@fontsource/ibm-plex-mono` (weight 400 only).

## Color

**Reconciled against `DESIGN.md` §3 — every hex value and token name below is copied verbatim from `DESIGN.md`, which is the authoritative source.** 60/30/10 discipline is preserved exactly as `DESIGN.md` states it: `paper` + `paper-raised` carry ~60% of any screen, `ink` (chrome bands) carries ~30%, and `shutter` plus the reserved job-specific accents together never exceed ~10%.

| Token | Value | Role |
|-------|-------|------|
| `paper` | `#FBF1E4` | Primary page background for every route — the base surface everything else sits on. (Was "Cream" `#FFF8EF` in Revision 2 — hex corrected.) |
| `paper-raised` | `#FFFFFF` | Card/print surfaces sitting on `paper` — placeholder-page content cards, results/gallery/profile stub panels. (Unchanged from Revision 2's "Paper White.") |
| `paper-border` | `#E7DCC8` | Default 1–1.5px border on `paper-raised` cards. (Was "Card border" `#F0E4D3` in Revision 2 — hex corrected.) |
| `ink` | `#221A14` | Nav bar + footer background, camera/HUD chrome, and default body/heading text color on `paper`/`paper-raised` — one warm brown-black token doing double duty as both a surface color and the default text color, which is what keeps the palette disciplined instead of sprawling. Never pure `#000`/`#111`. (Was "Aperture Ink" / "Ink" `#1D1626` in Revision 2 — hex corrected; that value was a cooler purple-black closer to the generic near-blacks `DESIGN.md` explicitly avoids.) |
| `ink-soft` | `#6B5E4F` | Secondary/muted text on `paper` or `paper-raised` (e.g. placeholder body copy, captions). (Was "Ink-muted" `#5B5548` in Revision 2 — hex corrected.) |
| `shutter` | `#FF5A3C` | The single primary accent — one job: the single primary action per screen (Start Playing, Snap, Save). Never used for anything else. (Was "Shutter Coral" `#FF5A47` in Revision 2 — hex corrected.) |
| `shutter-ink` | `#221A14` | Text/icon color *on* `shutter` fills — dark-on-bright reads better than white-on-coral and matches `ink` (contrast holds well above AA; white-on-coral would fail AA for normal text). |
| `danger` | `#C81E3A` | Errors, destructive actions, mis-drop/failure states only. Deliberately cooler/more red than `shutter` so the two are never visually confusable. (Unchanged hex from Revision 2's "Ruby" — already matched `DESIGN.md`.) |

`shutter` is reserved for exactly: the single primary CTA button per screen; the active nav-link indicator (2px underline against the `ink` nav bar); and the **focus-visible outline ring on every interactive element** — a 2px `shutter` ring, no exceptions, never suppressed, per `DESIGN.md` §18. (This focus-ring requirement existed in Revision 2 and is restated here verbatim; it was at risk of being dropped when the reserved-for list was compressed into the table above, so it's called out explicitly.) Do **not** use `shutter` for: body links, secondary/ghost buttons, decorative icons/blobs (those use the Landing Gradient Wash, scoped below), or general hover states on non-CTA elements.

**Reserved functional accents (defined by `DESIGN.md`, not yet used by any Phase 1 screen):**

| Token | Value | Job | Phase 1 status |
|-------|-------|-----|-----------------|
| `viewfinder` | `#1E9E8C` | Live-tracking teal — reserved exclusively for gesture/optical HUD state: pinch confirmed, tracking lock, camera-ready dot. | Not used — Phase 1 has no live camera feed (that's Phase 2's GAME-01). Reserved so Phase 2 doesn't have to invent it. |
| `token-gold` | `#FFC531` | Score/currency/reward — points, tokens, streak counters, badge-unlock glow. Never a button or a link. | Not used — Phase 1's Results/Profile pages are static "coming soon" placeholders with no real score to display. Reserved for Phase 5+ (SCORE-01, PROF-01). |
| `neon-violet` | `#7B5CF0` | Puzzle-active state — the tile currently being dragged/solved; the *only* place this color appears. | Not used — Phase 1's `/game` route is a static placeholder, not an interactive puzzle grid. Reserved for Phase 2's GAME-04. |

Every one of these three carries the same disposition Revision 2 already gave `danger`/Ruby: documented, reserved, and explicitly not deployed against any live functionality that doesn't exist yet in this phase.

### Landing Gradient Wash (decorative-only, Home hero background exclusively)

**Reconciliation, replacing Revision 2's "Decorative Motif Palette":** Revision 2 treated these four colors as an app-wide "Decorative Motif Palette" — used for landing gradient blobs, but also for per-route stub-page icon tints, a puzzle-grid icon accent on `/game`, and a card-shadow tint on every `PlaceholderCard`. `DESIGN.md` §10 and §21 reserve decorative color exclusively for "Home and other promotional surfaces... and even there, sparingly," and §3's accent discipline requires every color to have exactly one job. Phase 1's five stub routes (`/game`, `/results`, `/gallery`, `/profile`, `/share/:slug`) are plain informational placeholders, not promotional surfaces, so they no longer receive decorative color. These four hues are kept — `DESIGN.md` explicitly authorizes "soft abstract gradients" as the landing hero's decorative treatment without pinning specific hex values — but are re-scoped to that one context only, and one is renamed to avoid confusion with `DESIGN.md`'s own token names.

| Name | Value | Reserved for |
|------|-------|---------------|
| Flash Pink | `#FF3D9A` | Home hero's background gradient blobs and the tilted polaroid/photo-strip decoration — landing hero only. |
| Lens Blue | `#2F80ED` | Home hero's aperture-ring stroke graphic and corner-bracket framing marks — landing hero only. (Renamed from "Viewfinder Blue" in Revision 2 — that name collided with `DESIGN.md`'s `viewfinder` token, an unrelated teal reserved for live HUD state.) |
| Darkroom Violet | `#8B5CF6` | Home hero's background gradient blobs — landing hero only. Distinct hue and job from `DESIGN.md`'s `neon-violet` (`#7B5CF0`, puzzle-active-tile state) — the two must never be treated as interchangeable. |
| Flash Lime | `#D6F24C` | Home hero's highest-contrast decorative pop, used most sparingly of the four — landing hero only. |

**Hard rules, corrected for Revision 3:**
- These four colors appear **only** inside the Home (`/`) hero's decorative background layer (gradient blobs, aperture ring, halftone-adjacent shapes, corner brackets, the photo-strip decoration). They do **not** appear on any stub page's icon, on any card shadow, on the puzzle-grid motif, on a badge, or anywhere else in the app.
- Any time one of these four colors is used as a solid fill large enough to contain text or an icon, pair it with `ink` foreground — never white/cream — because Pink, Lens Blue, and Lime especially do not reliably clear 4.5:1 against white at typical fill sizes. (Unchanged rule from Revision 2, still correct.)
- They are never used for a second competing CTA and never fill more than a small decorative shape at a time — "confetti," not competing brand colors. (Unchanged from Revision 2.)

## Visual Motif: Making the Camera/Photobooth/Puzzle Concept Visible

This section still answers "make the camera/photobooth/puzzle concept visible in the visual language," now reconciled to `DESIGN.md`'s "toolkit, not checklist" principle (§1.4): each motif below is scoped to one context and is not sprinkled onto every screen.

1. **Viewfinder corner brackets** (Home hero only) — four small L-shaped bracket marks (Lens Blue or `ink`, 2px stroke) positioned at the corners of the hero content area on `/`, echoing the two-hand index-finger framing rectangle that is the actual GAME-02 capture gesture.
2. **Camera-aperture ring graphic** (Home hero only) — a large, low-opacity (10–15%) concentric-circle SVG graphic (Darkroom Violet or `ink` stroke) placed behind the hero headline, suggesting an aperture iris opening — decorative, not literal.
3. **Halftone/dot-grid texture** (Home hero only) — a subtle (4–6% opacity) dot-grid pattern across the `paper` hero background, evoking printed-photo halftone texture. CSS `radial-gradient` repeating pattern is sufficient; no image asset required.
4. **Landing Gradient Wash blobs** (Home hero only) — 2–3 large, heavily blurred (`blur-3xl` equivalent, ~24–40% opacity) color blobs using Flash Pink + Darkroom Violet + Lens Blue positioned behind hero content for depth, never behind body text (contrast risk). Reconciliation: these three colors and this placement are unchanged from Revision 2, only the surrounding palette scope/naming was corrected above.
5. **Tilted polaroid/photo-strip decorative stack** (Home hero only) — a small cluster of 2–3 rotated (−4° to +6°), stacked **plain white rectangle** "photo" placeholders near the bottom of the hero, foreshadowing the photo-strip gallery output (GAME-07) users will eventually produce. These are plain/blank print-shaped rectangles, not filled with fake photographic content — matching `DESIGN.md` §10's requirement that decorative surfaces work "beautifully when no user photos exist yet" via plain color/gradient cards in the print frame shape, not placeholder imagery.
6. **Puzzle-grid motif** (`/game` route only) — a subtle 3×3 grid outline (matching the actual `GRID` constant from the legacy engine) used as a decorative background element near the `/game` `PlaceholderCard`. **Reconciliation:** Revision 2 tinted this Flash Pink; per the Landing Gradient Wash re-scoping above, `/game` is not the Home hero, so this motif is now rendered in `ink` at low opacity instead of a Landing Gradient Wash color.
7. **Shutter-click micro-interaction** (global — every primary button) — primary CTA buttons scale to `1.03` and gain a soft `shutter`-tinted shadow bloom on hover/focus (150–200ms ease), and compress to `0.97` on active/press — modeled after the tactile feel of pressing a camera shutter button. **Reconciliation:** per `DESIGN.md` §19, this entire scale/glow effect must reduce to an instant, motion-free state change under `prefers-reduced-motion` — not stated in Revision 2, added here.

None of the above require new image assets — all are achievable with CSS gradients, SVG strokes, and existing `lucide-react` icons, so this revision introduces no new asset-pipeline dependency.

## Component Styling Approach

- **Buttons:** `rounded-2xl` (not full pill). Primary: `shutter` fill, `shutter-ink` text, `shutter`-tinted shadow on hover (`shadow-lg shadow-[#FF5A3C]/25`), scale 1.03 hover / 0.97 active, 150–200ms transition. Secondary/ghost: transparent or `paper-raised` fill, 1.5px `ink` border, no shadow, same scale-on-press feedback for consistency. **Reconciliation:** hex updated to `shutter`'s corrected value; `prefers-reduced-motion` now required — under that setting, hover/active scale and the shadow bloom reduce to an instant, non-animated state change (opacity/color changes are fine; transform/scale animation is not).
- **Cards (`PlaceholderCard` and future content cards):** `paper-raised` surface, `rounded-2xl` (20px), 1–1.5px `paper-border`, soft ambient shadow tinted with `ink` at low opacity (`shadow-xl shadow-[#221A14]/8`) rather than pure gray/black or a job-specific accent color. **Reconciliation:** Revision 2 tinted this shadow with Darkroom Violet — a Landing Gradient Wash color now scoped to the Home hero only — so the shadow tint is corrected to neutral `ink`. On hover: lift (`-translate-y-1`) plus a very slight rotate (`rotate-[-1deg]` or `rotate-[1deg]`, alternating or randomized per card) — evokes physically handling a printed photo; under `prefers-reduced-motion`, this reduces to no lift/rotate. **Reconciliation:** Revision 2's optional per-route icon, individually tinted from the Decorative Motif Palette (e.g. Flash Pink for `/gallery`, Lens Blue for `/game`), is removed — stub-page icons, where used, render in `ink` only (see the Route table below), since decorative color is now Home-only per `DESIGN.md`.
- **Nav bar:** unchanged structural pattern from Revision 2 (persistent top nav, `h-16`, `ink` background, wordmark left, links right ≥768px, hamburger + `Sheet` below 768px) — token values corrected to `shutter` for the wordmark and active-route underline/focus rings. **Compatibility check:** the nav already carries no live status chip and no forced CTA on every screen — it was already consistent with `DESIGN.md` §7 without needing a change.
- **Footer:** unchanged structural pattern (minimal centered line, Label style, reduced opacity) on the same `ink` surface as the nav bar, for visual bookending of the page.

## Landing Page Treatment

The `/` route gets the most decorative investment, per the developer's explicit note that "the landing page should feel exciting before the user clicks Start Playing" — and per `DESIGN.md` §21, this is also the *only* route where that decorative investment is authorized. Composition, top to bottom:

1. `paper` background with halftone dot-grid texture (item 3 above) and 2–3 blurred Landing Gradient Wash blobs (item 4 above) positioned behind the hero, never behind text.
2. Camera-aperture ring graphic (item 2) centered behind the headline at low opacity.
3. Viewfinder corner brackets (item 1) framing the headline + CTA block.
4. `Display` headline, `Body` subhead paragraph, single primary CTA button ("Start Playing," `shutter` fill, `shutter-ink` text, shutter-click micro-interaction) linking to `/game` — copy strings unchanged from the Copywriting Contract below.
5. Below the fold or adjacent to the CTA: the tilted polaroid/photo-strip decorative stack (item 5, plain rectangles per the reconciliation above), foreshadowing the photo-strip output feature.

This treatment is achievable entirely within `HomePage.tsx` using Tailwind utilities + inline SVG/CSS gradients — no new asset pipeline, no new dependency beyond the font swap already listed. **Compatibility check against `DESIGN.md` §6:** this composition already puts one hero element (the headline + CTA block) at the visual center with supporting decoration only framing it, not competing with it — no change needed to the composition itself, only to the token values used within it (above).
